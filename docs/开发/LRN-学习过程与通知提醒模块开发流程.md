# LRN 学习过程与通知提醒模块开发流程

## 1. 开发定位

LRN 负责学习任务、学习进度、学习行为、通知中心、提醒规则和通知偏好。它依赖 AUTH 获取当前用户，依赖 CRS 获取课程与成员关系，并接收 LAB、HWK、GRD 等模块的业务事件。

首版不要一开始做 WebSocket 或复杂实时推送。详细设计允许通知以站内消息为主，先实现站内通知、已读状态和轮询即可。

## 2. 详细设计阅读入口

开发前先阅读：

- `docs/最终提交/软件详细设计说明书.md` 的 `3.3 学习过程与通知提醒模块（LRN）`
- `docs/过程/详细设计/LRN-学习过程与通知提醒-详细设计提交稿.md`
- LAB/HWK/GRD 的事件触发点说明，确认通知事件来源

## 3. 统一开发顺序

```text
1. 读 LRN 详细设计章节，确认 UI-LRN / API-LRN / SVC-LRN / DB-LRN / TC-LN 编号
2. 建学习任务快照、进度、行为、通知、通知状态、提醒规则、偏好表
3. 先写通知中心后端 API
4. 写通知创建、查询、已读、删除 Service
5. 写前端通知中心页面
6. 写业务事件接收接口和事件 DTO
7. 写学习任务中心、学习进度、行为仪表盘和提醒设置页面
8. 接入 AUTH 当前用户和 CRS 课程成员校验
9. 自测用户只能看自己的通知和任务
10. 与 CRS/LAB/HWK/GRD 联调通知事件
```

## 4. P0 最短交付

LRN 的 P0 是通知中心可用：

```text
业务模块触发通知事件
→ LRN 创建站内通知
→ 用户登录后看到通知列表
→ 用户标记已读
→ 点击通知跳转业务页面
```

在 LAB/HWK/GRD 尚未完成时，可以先提供事件接收接口和本地测试数据，前端通知中心必须先接真实通知 API。

## 5. 数据库与实体

按 DSD 建立以下表：

| 表 | 用途 |
| --- | --- |
| 学习任务快照表 | 聚合 CRS、LAB、HWK 的任务摘要，避免页面每次跨模块重查 |
| 学习进度表 | 保存课程、章节或任务维度进度 |
| 学习行为记录表 | 记录查看、提交、下载、完成等学习行为 |
| 通知表 | 保存通知标题、内容、分类、跳转目标、来源模块 |
| 通知状态表 | 保存用户维度已读、删除等状态 |
| 提醒规则表 | 保存截止前提醒、任务提醒等规则 |
| 通知偏好表 | 保存用户通知开关和分类偏好 |

通知本体和用户状态要分开，避免一个用户删除或已读影响其他用户。

## 6. 后端 API 与 Service

先实现通知中心：

| 功能 | 建议接口 | 完成标准 |
| --- | --- | --- |
| 创建通知 | 事件接收接口或内部 Service | 可由业务事件生成通知 |
| 查询通知列表 | `GET /api/v1/notifications` | 支持分页、分类、未读筛选 |
| 标记已读 | `PUT /api/v1/notifications/{notificationId}/read` | 只修改当前用户状态 |
| 批量已读 | `PUT /api/v1/notifications/read-all` | 当前用户通知批量已读 |
| 删除通知 | `DELETE /api/v1/notifications/{notificationId}` | 对当前用户隐藏或标记删除 |

随后实现：

- 业务事件接收：作业发布、实验发布、评测完成、成绩发布、成绩异议处理
- 学习任务中心：聚合课程、实验、作业任务摘要
- 学习进度：保存进度、查询课程或章节进度
- 学习行为：行为上报、个人统计
- 提醒规则：截止前提醒、通知偏好、手动扫描或登录触发

通知事件 DTO 至少包含来源模块、事件类型、课程编号、业务对象编号、接收人范围、标题、内容、跳转地址和幂等键。

## 7. 前端页面与交互

LRN 前端必须包含：

| 页面 | 完成标准 |
| --- | --- |
| 学习任务中心页 | 按课程、类型、状态筛选任务，展示任务卡片和截止状态 |
| 学习进度页 | 展示课程或章节进度，支持保存或刷新进度 |
| 学习行为仪表盘 | 展示个人学习行为统计 |
| 消息通知中心页 | 通知列表、未读标记、分类筛选、已读/删除操作、点击跳转 |
| 提醒规则设置页 | 配置截止提醒和通知偏好 |

通知中心应作为首个完成页面。页面必须显示加载、失败、空通知、未读数量、已读状态变化。

## 8. 权限、异常与一致性

必须覆盖以下边界：

- 用户只能查看自己的通知状态
- 删除通知不影响其他用户
- 非课程成员不能看到该课程任务和通知
- 事件重复投递时不能重复生成相同通知
- 业务对象已删除或无权限时，点击通知应给出清晰提示
- 普通通知使用 `publish` 尽力而为投递：有活动业务事务时只注册 after-commit 回调，回调仅把不可变通知快照提交到专用有界执行器；来源事务回滚时不得生成通知，提交后由工作线程使用独立新事务落库，避免提交回调持有来源连接时再同步申请数据库连接
- 普通通知调度被拒绝或落库失败时只记录告警，不反向污染已提交业务；当前执行器队列仅在内存中，尚未实现持久重试/outbox，进程退出或队列拒绝时允许丢失
- **v2 作业发布投影：** `assessment.homework.published.v2` 在 Assessment 的 Homework + outbox 本地事务提交后异步消费；Learning 必须仅使用有界 title、RFC3339 deadline 和 receiverScope=COURSE_ACTIVE_STUDENTS，禁止消费 roster。单个 `course.member.changed.v2` 不证明成员投影完整；仅当 Course 的原子 `course.membership.snapshot.v2` 已推进本地课程级 watermark 后，Learning 才能幂等生成任务/通知。否则必须 durable-defer 原作业 envelope，由 reconciliation 追平后按原 eventId 一次性收敛。Learning/broker 不可用不得回滚发布；仅本地事务失败使用 `503/HWK_5003` 并保持 DRAFT

LRN 不直接维护课程成员、实验提交、作业提交或成绩数据，只保存任务快照、通知和学习行为。

## 9. 测试与自测清单

| 测试点 | 验收标准 |
| --- | --- |
| 通知创建 | 可通过测试事件创建通知 |
| 通知查询 | 用户只能看到自己的通知 |
| 已读状态 | 单条已读和批量已读状态正确 |
| 删除通知 | 删除只影响当前用户 |
| 分类筛选 | 可按类型、课程、未读状态筛选 |
| 任务中心 | 可展示 CRS/LAB/HWK 任务摘要或测试快照 |
| 事件幂等 | 重复事件不会生成重复通知 |

## 10. 联调事件顺序

按以下顺序联调：

1. CRS 公告发布生成 LRN 通知
2. LAB 实验发布、评测完成、评分完成生成 LRN 通知
3. HWK 作业发布、评测完成、成绩发布生成 LRN 通知
4. GRD 成绩发布、异议处理生成 LRN 通知
5. 用户从通知点击跳转到对应课程、实验、作业或成绩页面

完成标准是通知从业务事件产生到前端展示、已读、跳转形成闭环。
