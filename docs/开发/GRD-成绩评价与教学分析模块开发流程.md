# GRD 成绩评价与教学分析模块开发流程

## 1. 开发定位

GRD 是结果模块，负责成绩项配置、来源成绩同步、总评计算、成绩管理、成绩发布、学生查询、统计分析和成绩异议复核。它依赖 AUTH 当前用户、CRS 课程成员名单，以及 LAB/HWK 的实验和作业成绩来源。

GRD 不自己造实验或作业成绩。实验和作业成绩必须来自 LAB/HWK 的来源成绩数据，GRD 只负责归集、计算、发布、查询、统计和复核。

## 2. 详细设计阅读入口

开发前先阅读：

- `docs/最终提交/软件详细设计说明书.md` 的 `3.6 成绩评价与教学分析模块（GRD）`
- `docs/过程/详细设计/GRD-成绩评价与教学分析-详细设计提交稿.md`
- LAB/HWK 的来源成绩 DTO 和评分完成事件
- CRS 的课程成员名单和教师权限校验接口

## 3. 统一开发顺序

```text
1. 读 GRD 详细设计章节，确认 UI-GRD / API-GRD / SVC-GRD / DB-GRD / TC-GR 编号
2. 建成绩项、成绩记录、总评、发布记录、变更日志、异议表
3. 写成绩项配置 API
4. 写来源成绩同步或导入 Service
5. 写总评计算 Service
6. 写教师成绩项配置、成绩总表、成绩明细和发布前端页面
7. 写学生成绩查询、成绩构成、成绩异议前端页面
8. 接入 AUTH 当前用户和 CRS 课程教师/成员权限校验
9. 补未发布不可见、手动调整留痕、来源变化重算等异常处理
10. 联调 LAB/HWK 来源成绩和 LRN 通知
```

## 4. P0 最短交付

GRD 的 P0 路径是：

```text
教师创建成绩项
→ 选择 LAB/HWK 来源任务
→ 同步来源成绩
→ 计算总评
→ 教师查看成绩总表
→ 教师发布成绩
→ 学生查看已发布成绩
```

如果 LAB/HWK 尚未完成，可先使用符合 `SourceGradeDTO` 的测试来源数据，但字段必须与联调契约一致。

## 5. 数据库与实体

按 DSD 建立以下表：

| 表 | 用途 |
| --- | --- |
| 成绩项表 | 成绩项名称、课程、来源模块、来源任务、权重、满分、是否计入总评 |
| 成绩记录表 | 学生单项成绩、来源类型、来源编号、原始分、折算分 |
| 总评表 | 学生课程总评、缺失状态、计算批次、发布状态 |
| 成绩发布记录表 | 发布范围、发布时间、发布人、版本 |
| 成绩变更日志表 | 手动调整前后值、原因、操作者 |
| 成绩异议表 | 学生异议内容、状态、处理结果、处理人 |

所有手动调整必须记录原因和日志。总评计算要能处理缺失成绩、来源成绩变化和重新同步。

## 6. 后端 API 与 Service

先实现成绩项配置：

- 创建成绩项
- 设置来源模块 `LAB` / `HWK`
- 选择来源任务
- 设置权重、满分、是否计入总评
- 校验权重和来源合法性

随后实现成绩归集和计算：

- 从 LAB 获取实验成绩
- 从 HWK 获取作业成绩
- 记录 `sourceType + sourceId`
- 支持重新同步
- 计算 `raw_score`、`weighted_score`、`final_score`
- 标记缺失成绩状态

再实现管理、发布、查询和复核：

- 教师成绩总表
- 成绩明细
- 手动调整成绩
- 发布成绩
- 学生查询已发布成绩
- 成绩统计
- 学生提交异议
- 教师处理异议

Service 层建议拆分为 `GradeItemService`、`SourceGradeSyncService`、`GradeCalculationService`、`GradePublishService`、`GradeReviewService`、`GradeStatisticsService`。

## 7. 前端页面与交互

GRD 前端必须包含：

| 页面 | 完成标准 |
| --- | --- |
| 成绩项配置页 | 教师配置来源、权重、满分和是否计入总评 |
| 教师成绩总表页 | 按课程查看学生总评和缺失状态 |
| 成绩明细页 | 查看单项成绩、来源任务、手动调整日志 |
| 成绩发布页 | 发布前预览，发布后学生可见 |
| 学生成绩查询页 | 学生查看已发布成绩、成绩构成和来源反馈 |
| 成绩统计页 | 平均分、最高分、最低分、分数段、缺失统计 |
| 成绩异议页 | 学生提交异议，教师处理并反馈结果 |

页面必须展示加载、失败、空状态、未发布不可见、缺失成绩、发布成功、异议处理中等状态。

## 8. 权限、异常与跨模块事件

必须覆盖：

- 未发布成绩学生不可见
- 学生只能查看自己的成绩
- 教师只能管理自己课程成绩
- 管理员可按设计查看或维护全局数据
- 手动调整必须填写原因并留痕
- 来源成绩变化后可重新同步和重算
- 权重配置不合法时拒绝保存
- 异议只能针对已发布成绩提交

跨模块协作：

- GRD 从 LAB/HWK 读取或接收来源成绩
- GRD 依赖 CRS 获取课程学生名单和教师权限
- GRD 发布成绩 → LRN 通知
- GRD 处理成绩异议 → LRN 通知

`SourceGradeDTO` 至少包含来源类型、来源编号、课程编号、学生编号、任务名称、原始分、满分、评分状态、更新时间。

## 9. 测试与自测清单

| 测试点 | 验收标准 |
| --- | --- |
| 成绩项配置 | 教师可创建来源成绩项并设置权重 |
| 来源同步 | LAB/HWK 测试成绩可导入 GRD |
| 总评计算 | 原始分、折算分、总评和缺失状态正确 |
| 成绩发布 | 发布前学生不可见，发布后学生可见 |
| 手动调整 | 调整必须记录原因和变更日志 |
| 统计分析 | 平均分、最高分、最低分、分数段正确 |
| 成绩异议 | 学生可提交，教师可处理，状态流转正确 |
| 权限边界 | 学生不能看他人成绩，教师不能管理非本人课程 |

## 10. 联调顺序

1. AUTH → GRD：当前用户和角色权限
2. CRS → GRD：课程学生名单和教师权限
3. LAB → GRD：实验成绩来源
4. HWK → GRD：作业成绩来源
5. GRD → LRN：成绩发布和复核通知
6. 学生端：从成绩查询页跳转来源任务反馈

完成标准是来源成绩进入 GRD、教师配置并发布总评、学生查看成绩和提交异议的路径可演示。
