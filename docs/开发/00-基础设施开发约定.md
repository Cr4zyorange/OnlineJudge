# 基础设施开发约定

本文件约束各模块在正式开发时共同使用的基础设施。模块负责人实现 AUTH、CRS、LRN、LAB、HWK、GRD 时，应优先复用这里列出的后端包、前端请求层和跨模块契约，避免在各自模块里重复定义登录态、课程权限、通知事件、评测结果或来源成绩对象。

## 1. 后端统一登录态

后端统一使用 `com.onlinejudge.common.security.CurrentUser` 表示当前用户，Controller 可直接声明参数：

```java
public ApiResponse<?> example(CurrentUser currentUser) {
    long userId = currentUser.id();
    boolean teacher = currentUser.hasRole("TEACHER");
}
```

当前阶段 AUTH 尚未完整落库，`HeaderCurrentUserProvider` 先从以下请求头解析登录态，后续 AUTH 实现 JWT/Session 后只需要替换 `CurrentUserProvider`：

| 请求头 | 含义 |
| --- | --- |
| `X-User-Id` | 当前用户 ID |
| `X-Username` | 当前用户名，可为空 |
| `X-User-Role` | 平台角色，如 `STUDENT`、`TEACHER`、`ADMIN` |
| `X-Permissions` | 逗号分隔权限码，如 `course:manage,grade:manage` |

未登录或登录态无效时抛出 `AuthenticationRequiredException`，统一返回 `ERR-AUTH-04` 和 HTTP 401。权限不足时优先使用 `AccessDeniedException`，统一返回 `ERR-AUTH-05` 和 HTTP 403。登录失败仍由 AUTH 登录服务返回 `ERR-AUTH-01`，账号禁用、冻结或锁定统一返回 `ERR-AUTH-03`。

## 2. CRS 课程权限客户端

涉及课程数据的模块不得信任前端传入的 `userId` 或自行维护课程成员关系，应通过 `CoursePermissionClient` 查询：

```java
coursePermissionClient.canViewCourse(courseId, currentUser.id());
coursePermissionClient.canManageCourse(courseId, currentUser.id());
coursePermissionClient.canManageCourseGrade(courseId, currentUser.id());
```

实现与边界以 `docs/开发/D6-三服务架构冻结-306.md` 和 `docs/开发/D6-三服务共享契约-306.md` 为准：

- 消费端统一使用 `com.onlinejudge.integration.course.CoursePermissionClient`（v1）；
- 生产端由 CRS 通过 `CoursePermissionProvider` 提供课程存在性、成员关系、管理权限和名单（`CrsCoursePermissionProvider` 只读 CRS 自己的课程数据）；
- `DefaultCoursePermissionClient` 是所有业务模块的默认实现：正式路径委托给 CRS 生产者，调用带 `onlinejudge.integration.course.timeout-ms`（默认 1000ms）有界超时，超时或下游不可用一律拒绝/空名单（fail-closed），**禁止**回退直连 CRS 表或实现；
- 仅 DEV/演示环境（`onlinejudge.auth.allow-header-auth=true`）允许以下请求头模拟 CRS 能力：

| 请求头 | 含义 |
| --- | --- |
| `X-Course-Ids` | 当前用户可访问课程 ID，逗号分隔，`*` 表示全部 |
| `X-Manageable-Course-Ids` | 当前用户可管理课程 ID，逗号分隔，`*` 表示全部 |

`ADMIN` 在 DEV 头模式下默认拥有全部课程访问和管理权限。`LAB`、`HWK`、`GRD`、`LRN` 开发时必须通过此客户端做课程存在性、成员关系和教师权限校验。

## 3. 跨模块公共契约

模块化单体当前仍在后端 `common` 与 `integration` 包中保留部分共享类型，但它们不是微服务契约。三业务服务开发必须以 `docs/开发/D6-三服务架构冻结-306.md`、`docs/开发/D6-三服务共享契约-306.md` 及其 OpenAPI/AsyncAPI 为唯一正本，不得把进程内 SPI、共享内部 Header 或跨模块实现依赖当作服务化路径：

| 包 | 用途 |
| --- | --- |
| `common.evaluation` | LAB/HWK 共用 `EvaluationTask`、`EvaluationResult`、`EvaluationStatus`、`Evaluator`、`SandboxExecutor` |
| `common.event` | CRS/LAB/HWK/GRD 向 LRN 发送 `NotificationEvent`，默认 `NoopNotificationEventPublisher` 可先占位 |
| `common.storage` | CRS/LAB/HWK 共享文件存储抽象 `FileStorageService` 与 `StoredFile` |
| `integration.grade` | LAB/HWK 向 GRD 暴露 `SourceGradeDTO` 与 `SourceGradeClient` |

实现业务模块时不得重新定义同名 DTO；如确需扩展字段，应先同步公共契约、测试和对应开发文档。

上表列出的是模块化单体现有 Java 包，不等同于服务化后的实现路径。新服务只能按 v2 的 `/internal/v2/**` 和事件制品实现对应 adapter；迁移期代码只用于保留既有闭环，不能作为新服务的跨进程降级实现。

## 4. 前端统一请求层

前端统一使用 `frontend/src/api/http.ts` 的 `request` 发起后端请求，它负责：

- 注入登录态请求头；
- 按统一 `ApiResponse<T>` 解包；
- 后端失败时抛出后端 `message`；
- 登录态缺失时在发请求前失败。

模块 API 封装示例：

```ts
import { request } from '../http';

export function listItems(courseId: number) {
  return request(`/api/v1/courses/${courseId}/items`);
}
```

测试或临时联调可用 `configureAuthContext` 注入当前用户。正式 AUTH 页面完成后，应由登录流程写入统一登录态，而不是各模块各自维护本地存储键。
