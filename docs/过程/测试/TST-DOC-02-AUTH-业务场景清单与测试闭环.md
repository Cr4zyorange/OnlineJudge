## 2 场景盘点结论

### 2.1 盘点范围

按 Issue #261 工作范围第 1 条核对以下内容：

| 盘点项 | 结论 |
| --- | --- |
| 注册、登录、退出与持续鉴权 | 拆分为四个独立目标：注册（SC-AUTH-01）、登录（SC-AUTH-02）、退出（SC-AUTH-03）、持续鉴权（SC-AUTH-04），能力锚点 `UC-AUTH-01-R` |
| 个人资料与密码安全 | 拆分为两个独立目标：资料维护（SC-AUTH-05）、修改密码（SC-AUTH-06），能力锚点 `UC-AUTH-01-P` |
| 管理员用户、角色与权限管理 | 拆分为三个独立目标：用户与账号状态（SC-AUTH-07）、用户角色分配（SC-AUTH-08）、角色与角色权限维护（SC-AUTH-09），能力锚点 `UC-AUTH-01-A` |
| 账号禁用/锁定、会话过期和越权拒绝 | 归入安全异常拦截（SC-AUTH-10）的主成功流与备选/异常路径，另被 SC-AUTH-02/04/07 复用 |
| 关键操作审计 | 独立目标审计写入与查询（SC-AUTH-11），同时作为 SC-AUTH-02/03/06/07/08/09/10 的 `include` 公共子流程 |

### 2.3 `include` 公共子流程

以下子流程不属于独立场景，由 SC-AUTH-01 ~ SC-AUTH-11 按需 `include`，实现与测试必须保证可复用、可独立验证：

| 子流程编号 | 名称 | 说明 | 被哪些场景复用 |
| --- | --- | --- | --- |
| C1 | 账号与密码校验 | 查询账号、校验密码哈希、校验账号状态；失败时维护连续失败计数与锁定截止时间；不暴露账号存在性 | SC-AUTH-01、SC-AUTH-02、SC-AUTH-06 |
| C2 | 会话/令牌签发与校验 | 登录成功签发带过期时间的会话或令牌；数据库只保存令牌摘要；校验签名、过期时间、撤销状态；退出/改密/禁用时作废会话 | SC-AUTH-02、SC-AUTH-03、SC-AUTH-04、SC-AUTH-06、SC-AUTH-07、SC-AUTH-10 |
| C3 | 角色菜单与权限摘要加载 | 登录成功后按角色返回菜单、权限摘要；前端据此控制入口展示，后端仍独立校验 | SC-AUTH-02、SC-AUTH-08、SC-AUTH-09 |
| C4 | 关键操作审计写入与查询 | 记录操作人、操作类型、操作对象、结果状态、客户端信息；不含明文密码与完整令牌；管理员可分页查询 | SC-AUTH-02、SC-AUTH-03、SC-AUTH-06、SC-AUTH-07、SC-AUTH-08、SC-AUTH-09、SC-AUTH-10、SC-AUTH-11 |
| C5 | 统一认证与权限拦截 | Bearer 令牌解析、当前用户上下文注入、账号状态校验、接口权限点校验；未登录 401、越权 403 | SC-AUTH-04、SC-AUTH-07、SC-AUTH-08、SC-AUTH-09、SC-AUTH-10 |

### 2.4 备选/异常路径

| 异常编号 | 场景 | 处理策略 | 接口/页面结果 | 对应 ERR-AUTH |
| --- | --- | --- | --- | --- |
| E1 | 错误凭据或账号不存在 | 统一提示，不暴露账号存在性；记录 `LOGIN_FAILURE` | 账号或密码错误 | ERR-AUTH-01 | SC-AUTH-02 |
| E2 | 账号被禁用或冻结 | 拒绝登录和业务访问；记录审计 | 账号状态异常，请联系管理员 | ERR-AUTH-03 | SC-AUTH-02、SC-AUTH-04、SC-AUTH-10 |
| E3 | 连续失败达到锁定阈值 | 写入失败计数与 `locked_until`，锁定期内拒绝登录 | 账号状态异常，请联系管理员 | ERR-AUTH-03 | SC-AUTH-02、SC-AUTH-10 |
| E4 | 令牌过期、伪造或已撤销 | 统一按未认证处理；不泄露令牌细节 | 登录已失效，请重新登录 | ERR-AUTH-04 | SC-AUTH-03、SC-AUTH-04、SC-AUTH-10 |
| E5 | 越权访问页面/接口/资源 | 后端权限点校验拒绝；必要时记录 `ACCESS_DENIED` | 无权限访问 | ERR-AUTH-05 | SC-AUTH-04、SC-AUTH-07、SC-AUTH-08、SC-AUTH-09、SC-AUTH-10 |
| E6 | 输入校验失败（非法账号/手机号/邮箱/密码等） | 参数校验拦截，安全包装错误 | 请求参数不合法或字段级提示 | AUTH_400 | SC-AUTH-01、SC-AUTH-05、SC-AUTH-06 |
| E7 | 审计日志写入失败 | 普通查询不中断；关键权限变更失败回滚 | 操作失败或稍后重试 | AUTH_409 / 统一异常 | SC-AUTH-11 |

### 5.2 缺口复核结论

按 Issue #261 工作范围第 7 条复核后：

- 关键业务规则、异常分支与断言质量已由既有自动化覆盖，未发现需要新增后端行为测试的核心缺口。
- 本次新增的自动化缺口为“真实页面/接口入口的多角色端到端闭环”，由 `frontend/tests/e2e/auth/` 补齐，直接复用共享入口。
- 前端 `AuthStatusView` 的 403/登录失效/账号状态页跳转已由 `http.spec.ts` 覆盖；E2E 直接断言登录提交后的 URL 与状态页视图，无手工跳转绕过。
- E2E 测试发现登录页触发 `ERR-AUTH-03` 后视图不切换的缺陷（DEF-003），已通过 #271 修复（PR #274，监听器提升至根组件），禁用/锁定两条 E2E 已改为真实跳转断言并复测通过。
