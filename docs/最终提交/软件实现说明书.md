# 软件实现说明书

## 1 概述

本文档说明“在线教学与实训平台”的实现情况，用于补齐需求、概要设计、详细设计、测试文档与部署文档之间的实现层闭环。本文档依据 `docs/最终提交/软件需求规格说明书.md`、`docs/最终提交/软件概要设计说明书.md`、`docs/最终提交/软件详细设计说明书.md`、`docs/最终提交/测试文档.md`、`docs/最终提交/部署文档.md` 以及代码目录编写。

系统实现围绕主流程展开：

```text
登录 -> 课程 -> 作业/实验 -> 提交/评测 -> 成绩 -> 通知
```

实现范围覆盖 AUTH、CRS、LAB、HWK、GRD、LRN 六个业务模块，后端提供 REST API、业务服务、数据库访问和评测/文件/安全公共能力，前端提供学生、教师、管理员三类入口页面。

## 2 运行与技术架构

| 层次 | 实际实现 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Vitest、vue-tsc | 代码位于 `frontend/`，页面位于 `frontend/src/views/`，模块 API 封装位于 `frontend/src/api/`。 |
| 后端 | Spring Boot 3.4.5、Java 21、Spring MVC、Spring JDBC、Validation | 代码位于 `backend/`，按 `auth/crs/lab/hwk/grd/lrn/common/integration` 分包。 |
| 数据库 | 本地 H2/MySQL 兼容模式，部署 MySQL 8.4 | 本地通过 `backend/src/main/resources/schema.sql` 和 `database/migrations/` 初始化；Docker 部署使用 `database/mysql/compose-schema.sql`。 |
| 评测 | `common/evaluation` 抽象，Fake/Docker 两种执行器 | Compose 默认 `ONLINEJUDGE_EVALUATION_SANDBOX_MODE=fake`，增强模式可切换到 Docker 沙箱。 |
| 文件存储 | 本地磁盘存储 | `LocalDiskFileStorageService` 负责课程资源、LAB 提交源文件、实验报告等文件落盘。 |
| 部署 | Docker Compose、Nginx 前端反向代理、后端容器、MySQL 容器 | 配置位于 `deploy/docker/` 和 `deploy/nginx/`。 |

后端统一以 `/api/v1` 为接口前缀，统一响应结构由 `common/web/ApiResponse` 和 `PageResponse` 承载。前端 `frontend/src/api/http.ts` 统一处理 Bearer Token、JSON、FormData、Blob 下载和 401/403 导航。

### 2.1 开发环境与构建运行

本地开发链路与 Docker Compose 教学部署链路分离，README 和部署文档中的运行口径如下。

| 场景 | 运行形态 | 入口与端口 | 构建/启动命令 | 说明 |
| --- | --- | --- | --- | --- |
| 本地一键开发 | Vite + Spring Boot + H2 | 前端 `http://127.0.0.1:5173/`；后端 `http://127.0.0.1:8080`；Vite 将 `/api` 代理到后端 | `./scripts/dev/start-dev.sh` | 脚本同时启动后端和前端；首次运行会补装 `frontend/node_modules`。 |
| 本地后端 | Spring Boot + H2 | `8080` | `cd backend && mvn spring-boot:run` | 使用 `backend/src/main/resources/application.properties`，默认 H2 文件库 `backend/data/onlinejudge`，演示数据初始化默认开启。 |
| 本地前端 | Vite dev server | `5173` | `cd frontend && npm install && npm run dev -- --host 127.0.0.1` | `frontend/vite.config.ts` 配置 `/api -> http://127.0.0.1:8080`。 |
| 前端静态构建 | Vite build | `dist/` 静态产物 | `cd frontend && npm run build`；类型检查为 `npm run typecheck` | Vite 构建入口包括 `index.html` 和 `courses/index.html`。 |
| 后端测试/打包 | Maven | Spring Boot jar | `cd backend && mvn test`；打包可执行 `mvn package` | Docker 后端镜像构建阶段使用 `maven:3.9.9-eclipse-temurin-21` 和 Java 21，并执行 `mvn -f backend/pom.xml -Dmaven.test.skip=true package` 生成运行 jar。 |
| Docker Compose 教学部署 | Nginx + Spring Boot + MySQL 8.4 | 默认 `http://127.0.0.1:8088`，由 `OJ_HTTP_PORT` 映射到前端容器 `80`；后端容器内 `8080`，MySQL 容器内 `3306` | `docker compose -f deploy/docker/compose.yml up -d --build` | 宿主机只要求 Docker/Compose；镜像内完成 Maven、Node、Nginx 构建与运行。 |

## 7 数据库与迁移

数据库实现分三类文件：

| 文件 | 用途 |
| --- | --- |
| `backend/src/main/resources/schema.sql` | 本地 Spring Boot/H2 基础 schema，主要覆盖 AUTH、CRS 基础表，并为本地启动提供可重复初始化入口。 |
| `database/migrations/*.sql` | 按模块拆分的迁移 SQL，供本地 H2 MySQL 兼容模式和迁移测试复核。 |

## 8 关键业务链路

1. 用户通过 `POST /api/v1/auth/login` 登录，AUTH 校验密码、账号状态并签发 Bearer Token。
2. 前端将 Token 写入本地登录态，后续业务请求由 `frontend/src/api/http.ts` 注入 `Authorization: Bearer ...`。
3. 教师通过 CRS 创建课程、章节、资源和公告，学生通过课程列表或邀请码加入课程。
4. LAB/HWK 发布实验或作业后，学生在课程内查看任务并提交代码、答案或报告。
5. LAB/HWK 提交先落库，再进入 Fake 或 Docker 评测路径，评测结果写入各自评测表并返回给页面。
6. 教师可批阅、重评、发布作业或实验成绩，评分和变更日志保留操作痕迹。
7. GRD 通过来源成绩客户端同步 LAB/HWK 成绩，按成绩项权重生成成绩记录和课程总评，并控制发布状态。
8. LRN 接收实验、作业、成绩等业务事件，生成站内通知；学生可在任务中心、通知中心和成绩页查看后续反馈。

## 9 安全与权限

系统采用 Bearer Token 登录态作为运行时身份来源，`onlinejudge.auth.allow-header-auth=false`，业务接口不信任用户自控身份 Header。后端公共安全能力位于 `common/security`，包括 `CurrentUserProvider`、`CurrentUserArgumentResolver`、`AuthRequiredInterceptor`、`AccessDeniedException` 等。

权限控制由两层组成：

- 平台角色与权限：AUTH 管理用户、角色、权限、会话和审计，管理员接口集中在 `/api/v1/admin/*`。
- 课程数据权限：CRS 维护课程成员与角色，LAB/HWK/GRD 通过课程权限客户端校验教师管理权限、学生成员身份和本人数据访问边界。

安全实现还包括密码哈希、会话撤销、账号状态检查、审计日志、统一异常响应、文件类型/大小约束、隐藏测试用例隔离、成绩发布前不可见、通知事件内部令牌配置和本地文件存储路径隔离。

## 13 实现范围与扩展能力

- 本版本按课程设计交付边界实现，自动评测以基础 IO/脚本执行和可切换沙箱为主，不实现商业 OJ 的大规模分布式评测集群。
- LAB 测试用例按实验创建/更新整体替换，独立 `/api/v1/labs/{labId}/testcases` CRUD 路由属于扩展能力；启用该能力时需同步测试文档、前端 API wrapper 和 Controller 测试。
- Compose 主线默认使用教学演示评测模式，真实 Docker 沙箱属于增强能力，需要宿主机 Docker、容器内 Docker CLI 和共享临时目录配置配合。
- 通知以站内通知为主，短信、邮件、WebSocket 推送等外部通道作为扩展能力保留。
- 文件存储采用本地磁盘，对象存储、访问签名、生命周期和容量治理属于生产部署扩展项。
- #222 只实现事务失败时成功补偿删除；底层复制中途失败可能留下部分文件，`FileStorageService.delete` 自身失败后也没有业务级孤儿扫描、告警/审计持久化或重试队列；源文件下载审计持久化同样属于后续运维扩展能力。
- 数据迁移脚本已经按模块拆分并提供 Compose 完整 schema，Flyway/Liquibase 等迁移版本管理工具属于工程化扩展。
- 性能验证覆盖课程设计规模和本地压测样本，生产级并发、长稳和安全加固需结合真实部署环境继续验证。
