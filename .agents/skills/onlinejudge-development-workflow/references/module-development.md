# 模块全栈纵向开发工作流

来源：`docs/提炼skills/module-full-stack-development-workflow.md`。适用于把模块所有权、详细设计或 issue 分解成可执行的全栈开发计划，或检查某模块交付是否纵向完整。

## 核心原则

每个模块负责人交付完整纵向切片，不允许"后端做完了、前端等别人"：

```text
数据库表 → 后端 API → Service 逻辑 → 前端页面 → 权限与异常处理 → 测试数据 → 自测 → 跨模块联调
```

系统是 B/S 架构：浏览器 → Vue3 前端 → Spring Boot REST API → MySQL/文件存储。表现层是模块交付的一部分，不是后续可选项。

## 通用工作顺序

```text
1. 读模块 DSD 章节
2. 确认 UI/API/SVC/DB/TC 追溯编号
3. 建表、实体、枚举、种子数据
4. 实现后端 CRUD 与核心 API
5. 实现 Service 业务流
6. 实现前端页面与 API 调用
7. 加 AUTH 权限校验
8. 课程数据加 CRS 课程成员校验
9. 加异常处理与前端状态
10. 自测至少一条可演示路径
11. 参与跨模块联调
```

不要先写页面：先让 API 契约和真实种子数据（或稳定联调契约）就绪，再立即接前端。

## 模块优先级

1. `AUTH`：解锁登录、当前用户、角色、权限、测试账号。
2. `CRS`：解锁课程、章节、资源、课程成员。
3. `LAB` 与 `HWK`：先对齐共享评测状态与 DTO，再各自实现。
4. `LRN`：先做站内通知与轮询，不做 WebSocket。
5. `GRD`：消费 LAB/HWK 来源成绩，不自造实验或作业成绩。

## 各模块 P0 切片

### AUTH
先交付：`POST /api/v1/auth/login`、`GET /api/v1/auth/me`、后端 JWT 过滤器/拦截器、前端 Token 存储与 Axios 拦截器、学生/教师/管理员测试账号、按角色落地或菜单路由。
页面：登录、注册、个人资料、改密码、用户管理、角色管理、权限分配、审计日志、403、会话过期。

### CRS
先交付：课程表与课程成员表、课程列表/详情 API、教师建课、学生加入课程、供其他模块使用的课程成员权限校验。
页面：课程列表、课程详情、课程管理、章节管理、资源管理、成员管理、公告管理。

### LRN
先交付：通知表与用户通知状态表、创建/列表/已读/批量已读/删除、通知中心前端、供 CRS/LAB/HWK/GRD 使用的事件 DTO。
页面：学习任务中心、学习进度、学习行为看板、通知中心、提醒规则设置。

### LAB
先交付：实验、测试用例、提交、评测、报告、成绩、成绩日志表；教师草稿/创建/发布流；学生详情与提交流；基本 IO 比对评测；教师评分与学生反馈。
页面：实验列表、实验详情、创建/编辑实验、学生提交、提交历史、教师评分、实验反馈、实验统计。
状态机先于实现明确：`DRAFT → NOT_OPEN → PUBLISHED → CLOSED → SCORE_PUBLISHED → ARCHIVED`。

### HWK
先交付：作业、客观题、测试用例、提交、评测、评审日志表；教师创建/发布流；学生文本/附件/代码提交流；客观题判分或代码 IO 比对；教师评审与学生反馈。详见 `hwk-module.md`。
与 LAB 协调共享：`EvaluationTask`、`Evaluator`、`SandboxExecutor`、`EvaluationResult` 及评测状态枚举。

### GRD
先交付：成绩项、成绩记录、最终成绩、发布记录、变更日志、申诉表；成绩项配置；LAB/HWK 来源成绩同步/导入；最终成绩计算；教师成绩表与发布；学生已发布成绩查询。
页面：成绩项配置、教师成绩表、成绩详情、成绩发布、学生成绩查询、成绩统计、成绩申诉。
必须使用 `SourceGradeDTO` 或等价契约，不得直接读或重建 LAB/HWK 内部成绩。

## 跨模块契约

| 调用方 | 提供方 | 契约 |
| --- | --- | --- |
| CRS/LRN/LAB/HWK/GRD | AUTH | 当前用户 DTO、角色、权限码、登录失效行为 |
| LRN/LAB/HWK/GRD | CRS | 课程存在性、课程成员资格、课程教师权限、学生名单 |
| LAB/HWK | LRN | 发布、截止、评测完成、出分完成的通知事件 |
| GRD | LAB/HWK | 来源成绩 DTO、分值范围、提交/评测状态、更新时间 |
| LAB/HWK | GRD | 出分后的成绩推送或来源成绩查询语义 |
| GRD | LRN | 成绩发布与申诉结果通知事件 |

业务模块不得信任前端 `userId`，不得直读其他模块内部表，不得复制 AUTH 或 CRS 权限逻辑。

## Issue 完成标准

以下全部成立才算完成：表和实体存在；后端 API 可调用；Service 逻辑符合详细设计；前端页面能完成操作；前端有加载/成功/失败/空状态；API 受 AUTH 保护；课程数据受 CRS 成员校验保护；异常返回明确错误码与信息；种子或测试数据存在；至少一条可演示路径端到端可跑。

## 集成顺序

```text
1. AUTH → CRS
2. CRS → LAB
3. CRS → HWK
4. LAB/HWK → GRD
5. LAB/HWK/GRD → LRN
6. 全链路：登录 → 课程 → 学习任务 → 作业/实验提交 → 评测/评分 → 成绩发布 → 学生通知与成绩查询
```

## 演示稳定路径

优先保护这条链路，胜过任何单页的功能深度：

```text
管理员维护用户 → 教师登录 → 教师建课 → 学生加入课程
→ 教师发布资源/作业/实验 → 学生查看任务并提交
→ 系统评测或教师评分 → 教师配置成绩项并汇总 → 教师发布成绩
→ 学生查看成绩与通知
```

## 自检清单

标记模块完成前检查：模块有 DB/API/Service/前端覆盖；UI/API/SVC/DB/TC 编号可追溯到详细设计；用 AUTH 当前用户而非前端身份；课程数据用 CRS 成员校验；LAB/HWK 共享评测状态与结果契约；GRD 消费 LAB/HWK 来源成绩；LRN 拥有通知状态而其他模块只发事件；前端覆盖加载/成功/失败/空/无权限/会话过期；至少一条自测路径和一条跨模块集成路径跑过。

```bash
rg -n "UI-|API-|SVC-|DB-|TC-" docs/开发 docs/最终提交/软件详细设计说明书.md
rg -n "EvaluationResult|SourceGradeDTO|NotificationEvent|CoursePermissionClient|/api/v1" docs/开发 docs/最终提交/软件详细设计说明书.md
git diff --check -- docs/开发 docs/提炼skills
```
